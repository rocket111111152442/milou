## 3. Migration PostgreSQL

- Schéma dans `db/migrations` (5 fichiers), suivi par `waverti_migrations.schema_migrations` avec verrou
  consultatif. Plus aucun objet Supabase (`auth.*`, rôles `anon` / `authenticated`) : vérifié par test.
- Isolation : chaque lecture utilisateur s'exécute sous le rôle `app_user` avec `app.user_id` ; les tables
  d'identité et d'exploitation lui sont inaccessibles. 9 tests RLS + test d'isolation E2E entre comptes.
- Développement : `infra/docker/docker-compose.dev.yml`. Production : `infra/docker/docker-compose.postgres.yml`
  (TLS, `scram-sha-256`) — **non déployé** (aucun serveur souscrit).
- Sauvegarde puis restauration dans une base neuve, avec contrôle des tables et de la RLS : test automatisé
  réussi [Local]. En CI, ce test est ignoré si `pg_dump` n'a pas la même version que le serveur.
- L'ancien système (Supabase) n'avait pas de données réelles ; il a été retiré après que la nouvelle
  authentification a passé l'ensemble des tests (249 unitaires/intégration au moment du retrait, 35 E2E web,
  5 E2E desktop Linux).

créer un sujet de test ; chaque requête apparaîtra dans Administration → Coûts.
